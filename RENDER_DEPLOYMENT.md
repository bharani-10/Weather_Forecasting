# Deploy to Render.com - Step by Step Guide

## Prerequisites
- GitHub account
- Render account (sign up at https://render.com)
- Your code pushed to GitHub repository

## Step 1: Push Your Code to GitHub

```bash
# Initialize git if not already done
git init

# Add all files
git add .

# Commit your changes
git commit -m "Prepare for Render deployment"

# Add your remote repository
git remote add origin https://github.com/yourusername/your-repo-name.git

# Push to GitHub
git push -u origin main
```

## Step 2: Create a Web Service on Render

1. Go to https://render.com and sign in
2. Click **"New +"** button and select **"Web Service"**
3. Connect your GitHub repository:
   - Click **"Connect GitHub"** (if not already connected)
   - Select your repository from the list

## Step 3: Configure Your Web Service

Fill in the following settings:

### Basic Settings:
- **Name**: `weather-forecasting` (or your preferred name)
- **Region**: Choose closest to your users
- **Branch**: `main` (or your default branch)
- **Root Directory**: (leave blank)
- **Runtime**: `Python 3`

### Build & Deploy Settings:
- **Build Command**: `./build.sh`
- **Start Command**: `gunicorn weather_prediction.wsgi:application`

## Step 4: Add Environment Variables

Click **"Advanced"** and add these environment variables:

| Key | Value | Notes |
|-----|-------|-------|
| `PYTHON_VERSION` | `3.13.0` | Python version |
| `DJANGO_SETTINGS_MODULE` | `weather_prediction.settings_production` | Use production settings |
| `DEBUG` | `False` | Never use True in production |
| `SECRET_KEY` | (Click "Generate") | Let Render generate a secure key |
| `WEATHER_API_KEY` | `your_api_key` | Get from openweathermap.org |

## Step 5: Add PostgreSQL Database (Optional but Recommended)

For production, it's recommended to use PostgreSQL instead of SQLite:

1. In your Render dashboard, click **"New +"** → **"PostgreSQL"**
2. Name it (e.g., `weather-forecasting-db`)
3. Choose the **Free** plan
4. Click **"Create Database"**
5. After creation, copy the **Internal Database URL**
6. Go back to your Web Service → **Environment** tab
7. Add a new environment variable:
   - **Key**: `DATABASE_URL`
   - **Value**: (paste the Internal Database URL)

## Step 6: Deploy!

1. Click **"Create Web Service"** button
2. Render will automatically:
   - Clone your repository
   - Run the build script
   - Install dependencies
   - Collect static files
   - Run migrations
   - Start the server

3. Monitor the deployment logs in real-time

## Step 7: Access Your Application

Once deployment is complete (typically 2-5 minutes):
- Your app will be available at: `https://your-app-name.onrender.com`
- Click the URL at the top of your service page

## Troubleshooting

### Build Fails
- Check the logs for specific errors
- Ensure all dependencies are in `requirements.txt`
- Verify `build.sh` has execution permissions

### Database Errors
- Make sure `DATABASE_URL` environment variable is set
- Check that migrations ran successfully in the build logs

### Static Files Not Loading
- Verify `collectstatic` ran during build
- Check `STATIC_ROOT` and `STATICFILES_STORAGE` settings

### Application Not Starting
- Check `Start Command` is correct: `gunicorn weather_prediction.wsgi:application`
- Review application logs for errors
- Ensure `DJANGO_SETTINGS_MODULE` is set correctly

## Important Notes

### Free Tier Limitations:
- Services spin down after 15 minutes of inactivity
- First request after spin-down will be slow (30-60 seconds)
- 750 hours/month of runtime
- SQLite database will reset on each deploy (use PostgreSQL for persistence)

### Continuous Deployment:
- Render automatically deploys when you push to your GitHub branch
- You can disable auto-deploy in service settings if needed

### Custom Domain:
1. Go to your service **Settings** → **Custom Domain**
2. Add your domain name
3. Update your DNS records as instructed by Render

## Environment Variables Reference

```bash
# Required
SECRET_KEY=<auto-generated-by-render>
DJANGO_SETTINGS_MODULE=weather_prediction.settings_production
DEBUG=False

# Optional but Recommended
WEATHER_API_KEY=<your-openweathermap-api-key>
DATABASE_URL=<postgresql-url-from-render>

# Optional
ALLOWED_HOSTS=yourdomain.com,www.yourdomain.com
```

## Updating Your Application

To deploy updates:

```bash
# Make your changes
git add .
git commit -m "Your update message"
git push origin main
```

Render will automatically detect the push and redeploy your application.

## Monitoring

- **Logs**: View real-time logs in the Render dashboard
- **Metrics**: Monitor CPU, memory, and bandwidth usage
- **Shell**: Access your application shell via Render's web terminal

## Cost Optimization

The free tier is great for testing, but for production:
- Consider upgrading to a paid plan for always-on service
- Use PostgreSQL instead of SQLite
- Enable Redis for caching (add as a separate Render service)
